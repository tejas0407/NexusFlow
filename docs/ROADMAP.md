# Starter Roadmap

This roadmap is a planning scaffold, not a confirmed specification. Adjust it after the mentor clarifies the project requirements and schedule.

## Phase 1 — Confirm scope

- Review the assignment and collect mentor requirements.
- Identify users, device/simulator inputs, telemetry fields, dashboard views, rule conditions, and expected actions.
- Confirm timeline, acceptance criteria, and permitted external services.
- Write user stories and a short definition of done.

## Phase 2 — Design the system

- Choose the technology stack based on confirmed requirements.
- Sketch the main user flows and dashboard.
- Define telemetry, device, and rule data shapes.
- Document ingestion, storage, rule evaluation, and alert flows.
- Identify privacy, security, reliability, and performance needs.

## Phase 3 — Build a thin end-to-end slice

- Create the application skeleton and local development setup.
- Add one device or simulator input and a small telemetry path.
- Display recent readings in the UI.
- Add one representative rule and show its evaluation result.
- Keep secrets in local environment configuration, not source control.

## Phase 4 — Complete and refine

- Implement the agreed dashboard, device management, rule management, and history features.
- Handle invalid inputs, missing data, reconnects, and rule edge cases.
- Improve accessibility and responsive behavior.
- Record setup and operation instructions.

## Phase 5 — Review and submit

- Check the agreed acceptance criteria with the mentor.
- Prepare project documentation, report, and presentation.
- Capture a clear demo flow and note known limitations.
- Submit periodic progress updates and final deliverables.

## Working log

Add dated entries as work proceeds. Record completed outcomes, decisions, blockers, and next steps without including confidential company information.
